# Haskell Zip Alignment Debug Lab

`zip` が短い方のリストで停止する契約を知らず、人数と時刻の不一致を黙って切り捨てる不具合を再現するラボです。`Maybe` を返す型があっても、実装が件数不一致を検査しなければデータ消失を防げないことをHspecで確認します。

## 前提環境

| 項目 | バージョン |
|---|---:|
| GHC | 9.4.7 |
| cabal-install | 3.8.1.0 |
| Hspec | 2.10.10 |

## 不具合の再現

不具合コミットは `33cb0c5` です。不具合状態では、人物が2人で時刻が1件しかない場合も、1組だけの割当を `Just` で返します。

```bash
cabal test --offline --test-show-details=direct
```

失敗出力は `artifacts/failing-test-output.txt`、GHCiでの型と対照入力は `artifacts/ghci-observation.txt` に保存しています。

## 修正後の検証

修正コミットは `2581205` です。修正後も同じコマンドを実行します。件数不一致は `Nothing`、一致時は全要素を含む割当になることを確認します。

## 学べること

| 概念 | このラボで確かめること |
|---|---|
| `zip` | 短い方の入力が尽きると停止し、長い方の余剰要素を捨てる。 |
| `Maybe` | 型が失敗を表現しても、実装が失敗条件を判定しなければ契約を守れない。 |
| データ完全性 | 二つのリストを対応付ける前に、件数一致を検証する。 |

詳細な調査は `docs/debugging-record.md` に記録します。
